DealLens 4.1 — Flipkart Live status (includes the 4.0.2 HTTP 429 fix; you can skip pushing 4.0.2)

FIRST: run supabase/migrations/002_deallens_flipkart_status.sql in the DispatchLens Supabase project
(SQL Editor > New query > paste > Run). It only adds two deallens_ tables for Flipkart results.

WHAT'S NEW
- Live status has an Amazon / Flipkart / Both switch.
  Flipkart: each FSN's own product page is checked (the link from the master sheet). It reports
  Live & buyable, Other variant shown (Flipkart showed a different FSN), Sold out / Discontinued,
  Coming soon / Not buyable, or Couldn't check. Price is compared with the Flipkart deal file (or
  your plan, or the catalogue price — the same "Compare price to" setting as Amazon).
  How it reads the page was worked out from 3 real Flipkart pages fetched today: the page states the
  FSN it is showing, the price and InStock/OutOfStock in one structured block.
  Both: one row per product, Amazon and Flipkart side by side. Filters pick a product if either side
  matches, and still show both sides.
- The Deal prices tab's Flipkart "Live check" now uses the same reading, and also fills Live status.
- The 9:00 am daily check (if switched on) now covers Flipkart too: half the time for Amazon, half
  for Flipkart, longest-unchecked first; anything not reached goes first the next day.
- 4.0.2 fix included: at most 2 Scrapingdog requests at a time (SCRAPINGDOG_CONCURRENCY to change),
  and HTTP 429 is retried with waits instead of shown as "Couldn't check".

WHAT WAS CHECKED
- tsc clean, next build clean, all tests pass (logic on your real files, Google key 14 paste forms,
  429 retry, Flipkart classifier incl. a swapped variant, sold out, pre-order, blocked page).
- Migration 002 ran twice on Postgres next to 001: approved device reads, pending device gets

- Built app driven in a browser against stand-in data: Flipkart view, Both view, filters, 390px width.
- Not tested here: real Flipkart checks through the deployed server (they will use your Vercel key).
